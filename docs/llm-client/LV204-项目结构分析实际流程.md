## 一、 概述

当 Claude Code 面对一个完全陌生的项目时，它不会全量遍历所有文件，也不会一次性读取整个目录树。相反，它采用"启动时自动注入少量上下文 + 按需定向搜索 + 并行调用 + 子代理委派"的组合策略，在探索效率和上下文窗口保护之间取得平衡。

本文档详细分析 Claude Code 从会话启动到完成项目结构分析的完整实际流程，涵盖启动时自动注入的上下文、核心探索工具的行为特征、三阶段探索工作流以及关键设计原则。

## 二、 启动时自动注入的上下文

Claude Code 在会话启动时，会自动将以下项目信息注入系统提示词，无需 AI 主动探索。这些信息构成了 AI 对项目的初始认知基础。

### 1. Git 状态（gitStatus）

[`getGitStatus()`](../../claude-code-source/src/context.ts#L36-L111) 在会话启动时自动执行，收集以下 Git 信息并注入系统提示词：

```typescript
// src/context.ts
export const getGitStatus = memoize(async (): Promise<string | null> => {
  const [branch, mainBranch, status, log, userName] = await Promise.all([
    getBranch(),
    getDefaultBranch(),
    execFileNoThrow(gitExe(), ['--no-optional-locks', 'status', '--short'], {...}),
    execFileNoThrow(gitExe(), ['--no-optional-locks', 'log', '--oneline', '-n', '5'], {...}),
    execFileNoThrow(gitExe(), ['config', 'user.name'], {...}),
  ])
  // ...
})
```

注入的内容包括：

| 信息项 | 来源命令 | 说明 |
|--------|----------|------|
| 当前分支 | `git branch` | 当前所在的 Git 分支 |
| 主分支 | `git symbolic-ref` | 通常用于 PR 的主分支名称 |
| 工作区状态 | `git status --short` | 已修改/暂存/未跟踪文件列表，最多 2000 字符 |
| 最近提交 | `git log --oneline -n 5` | 最近 5 条提交记录 |
| Git 用户名 | `git config user.name` | 提交者名称 |

### 2. gitStatus 截断机制

工作区状态超过 2000 字符时会被截断：

```typescript
// src/context.ts
const MAX_STATUS_CHARS = 2000

const truncatedStatus =
  status.length > MAX_STATUS_CHARS
    ? status.substring(0, MAX_STATUS_CHARS) +
      '\n... (truncated because it exceeds 2k characters. If you need more information, run "git status" using BashTool)'
    : status
```

截断后附加提示，引导 AI 在需要完整状态时通过 Bash 工具手动获取。

### 3. gitStatus 注入格式

最终注入系统提示词的格式：

```
This is the git status at the start of the conversation. Note that this status 
is a snapshot in time, and will not update during the conversation.

Current branch: main
Main branch (you will usually use this for PRs): main
Git user: username
Status:
M src/index.ts
?? src/new-file.ts

Recent commits:
a1b2c3d feat: add new feature
d4e5f6g fix: resolve bug
```

【**注意**】该状态是会话启动时的快照，对话过程中不会自动更新。

### 4. CLAUDE.md 自动加载

如果项目根目录存在 `CLAUDE.md` 文件，其内容会被自动加载到每个会话的系统提示词中。`CLAUDE.md` 通常包含：

- 项目架构说明
- 常用构建/测试/运行命令
- 代码约定和规范
- 关键模块的入口说明

### 5. 工作目录路径

系统提示词中包含当前工作目录的绝对路径，AI 据此知道项目根目录的位置。

### 6. 不包含目录树

启动时自动注入的上下文**不包含完整的目录树结构**。Claude Code 没有在启动时自动生成目录树的功能。AI 需要通过工具调用主动探索文件结构。

## 三、 核心探索工具

系统提示词强制 AI 使用以下三个专用工具进行探索，而非 Bash 命令。

### 1. Glob 工具

[`Glob`](../../claude-code-source/src/tools/GlobTool/prompt.ts) 是基于 ripgrep 的文件模式匹配工具：

```typescript
// src/tools/GlobTool/prompt.ts
export const DESCRIPTION = `- Fast file pattern matching tool that works with any codebase size
- Supports glob patterns like "**/*.js" or "src/**/*.ts"
- Returns matching file paths sorted by modification time
- Use this tool when you need to find files by name patterns
- When you are doing an open ended search that may require multiple rounds of globbing and grepping, use the Agent tool instead`
```

#### 1.1 关键实现细节

来自 [`glob.ts`](../../claude-code-source/src/utils/glob.ts#L66-L99)：

```typescript
// src/utils/glob.ts
const noIgnore = isEnvTruthy(process.env.CLAUDE_CODE_GLOB_NO_IGNORE || 'true')
const hidden = isEnvTruthy(process.env.CLAUDE_CODE_GLOB_HIDDEN || 'true')
const args = [
  '--files',           // 列出文件而非搜索内容
  '--glob', pattern,   // 按模式过滤
  '--sort=modified',   // 按修改时间排序
  ...(noIgnore ? ['--no-ignore'] : []),  // 默认不遵守 .gitignore
  ...(hidden ? ['--hidden'] : []),        // 默认包含隐藏文件
]
```

#### 1.2 行为特征

| 特性 | 默认值 | 说明 |
|------|--------|------|
| `.gitignore` 遵守 | 否（`--no-ignore`） | 会搜索到 `node_modules`、`dist` 等目录 |
| 隐藏文件 | 包含（`--hidden`） | 会搜索到 `.env`、`.config` 等文件 |
| 排序方式 | 修改时间 | 最近修改的文件排在前面 |
| 底层引擎 | ripgrep | 内存效率高，适合大型代码库 |

#### 1.3 典型用法

| 模式 | 用途 |
|------|------|
| `**/*.ts` | 找到所有 TypeScript 文件 |
| `**/package.json` | 找到所有 Node.js 项目配置 |
| `**/*.md` | 找到所有文档文件 |
| `src/**/*` | 列出 src 目录下所有文件 |
| `*` | 列出根目录文件（模拟 `ls`） |

### 2. Grep 工具

[`Grep`](../../claude-code-source/src/tools/GrepTool/prompt.ts) 是基于 ripgrep 的内容搜索工具：

```typescript
// src/tools/GrepTool/prompt.ts
export function getDescription(): string {
  return `A powerful search tool built on ripgrep
  - ALWAYS use Grep for search tasks. NEVER invoke \`grep\` or \`rg\` as a Bash command.
  - Supports full regex syntax (e.g., "log.*Error", "function\\s+\\w+")
  - Filter files with glob parameter (e.g., "*.js", "**/*.tsx") or type parameter
  - Output modes: "content" shows matching lines, "files_with_matches" shows only file paths (default), "count" shows match counts
  - Use Agent tool for open-ended searches requiring multiple rounds`
}
```

#### 2.1 行为特征

| 特性 | 默认值 | 说明 |
|------|--------|------|
| `.gitignore` 遵守 | 是 | 不会搜索 `node_modules` 等忽略目录 |
| 输出模式 | `files_with_matches` | 默认只返回文件路径，不返回匹配内容 |
| 正则支持 | 是 | 支持完整 ripgrep 正则语法 |
| 文件类型过滤 | 是 | 支持按 `type`（如 `js`、`py`）或 `glob` 过滤 |
| 多行匹配 | 否（可选开启） | `multiline: true` 支持跨行模式 |

#### 2.2 与 Glob 的 .gitignore 差异

| 工具 | `.gitignore` 遵守 | 原因 |
|------|-------------------|------|
| `Glob` | 否（`--no-ignore`） | 文件名搜索需要覆盖所有文件 |
| `Grep` | 是 | 内容搜索默认排除依赖目录，减少噪音 |

### 3. Read 工具

`Read` 工具用于读取指定路径的文件内容：

| 特性 | 说明 |
|------|------|
| 默认行数限制 | 2000 行（可通过 `offset`/`limit` 分页读取） |
| 支持图片 | 支持 jpeg/jpg/png/gif/webp 格式 |
| 空文件处理 | 返回 "File is empty." |
| IDE 诊断 | 读取时可能返回 linter 错误和警告 |

## 四、 三阶段探索工作流

当 AI 被要求分析一个陌生项目时，典型流程分为三个阶段。

### 1. 阶段一：广度扫描

AI 并行发起多个搜索调用，快速建立项目全貌认知：

```
并行调用：
├─ Glob("**/*.md")           → 找到所有文档文件
├─ Glob("**/package.json")   → 找到项目配置（Node.js 项目）
├─ Glob("**/*.ts")           → 了解源码文件分布
├─ Glob("**/Makefile")       → 找到构建文件
├─ Grep("export.*function")  → 了解导出的函数
└─ Read("README.md")         → 读取项目说明
```

此阶段的目标是：

- 确定项目类型和技术栈
- 定位入口文件和配置文件
- 了解文档分布
- 识别源码文件的主要分布区域

【**关键**】此阶段不是遍历所有文件，而是用模式匹配快速定位关键文件类型。

### 2. 阶段二：深度阅读

基于阶段一的发现，AI 选择性地读取关键文件：

```
并行调用：
├─ Read("src/index.ts")          → 入口文件
├─ Read("src/config/index.ts")   → 配置模块
├─ Grep("class.* extends")       → 找到类继承关系
└─ Grep("import.*from")          → 了解模块依赖
```

此阶段的目标是：

- 理解核心模块的架构设计
- 追踪关键代码路径
- 识别可复用的现有函数和模式
- 理解模块间的依赖关系

### 3. 阶段三：委派子代理

当预计需要超过 3 次查询时，AI 委派 Explore 子代理进行大规模探索：

```
Task(
  subagent_type="Explore",
  prompt="分析这个项目的认证模块架构，包括中间件、路由、控制器..."
)
  → Explore 子代理在独立上下文中并行搜索
  → 使用 haiku 模型快速执行
  → 返回精炼报告，不污染主上下文
```

此阶段的目标是：

- 处理需要大量搜索的复杂探索任务
- 保护主代理上下文窗口免受原始搜索结果污染
- 利用子代理的并行搜索能力提高效率

## 五、 决策分层机制

### 1. 核心阈值

系统提示词中的决策指导来自 [`prompts.ts`](../../claude-code-source/src/constants/prompts.ts#L374-L381)：

```typescript
// src/constants/prompts.ts
`For simple, directed codebase searches (e.g. for a specific file/class/function) use ${searchTools} directly.`,
`For broader codebase exploration and deep research, use the ${AGENT_TOOL_NAME} tool with subagent_type=${EXPLORE_AGENT.agentType}. This is slower than using ${searchTools} directly, so use this only when a simple, directed search proves to be insufficient or when your task will clearly require more than ${EXPLORE_AGENT_MIN_QUERIES} queries.`,
```

阈值常量 [`EXPLORE_AGENT_MIN_QUERIES`](../../claude-code-source/src/tools/AgentTool/built-in/exploreAgent.ts#L59) = 3。

### 2. 决策矩阵

| 场景 | 预计查询次数 | 使用工具 | 特点 |
|------|-------------|----------|------|
| 找特定文件/类/函数 | ≤ 3 | `Glob`/`Grep`/`Read` 直接调用 | 快速、低延迟、结果直接进入主上下文 |
| 广泛代码库探索 | > 3 | `Task` + `Explore` 子代理 | 并行搜索、保护主上下文、使用 `haiku` 模型 |
| 后台异步研究 | 不限 | `Task` 创建 Fork | 后台运行、不阻塞用户交互 |

### 3. 启用条件

决策分层指导在以下条件同时满足时注入：

| 条件 | 来源 |
|------|------|
| Agent 工具可用 | 工具注册检查 |
| `areExplorePlanAgentsEnabled()` 为 true | GrowthBook `tengu_amber_stoat` flag，默认 true |
| Fork 模式未启用 | `!isForkSubagentEnabled()` |

## 六、 关键设计原则

### 1. 按需读取，非全量遍历

系统提示词的核心指导：

```typescript
// src/constants/prompts.ts
`In general, do not propose changes to code you haven't read. If a user asks about or wants you to modify a file, read it first. Understand existing code before suggesting modifications.`,
```

这是**按需读取**——只读与当前任务相关的文件，而非全量读取所有文件。

### 2. 并行调用最大化

```typescript
// src/constants/prompts.ts
`You can call multiple tools in a single response. If you intend to call multiple tools and there are no dependencies between them, make all independent tool calls in parallel. Maximize use of parallel tool calls where possible to increase efficiency.`
```

AI 会同时发起多个 `Glob`/`Grep`/`Read` 调用，而非串行等待。

### 3. 专用工具优先于 Bash

```typescript
// src/constants/prompts.ts
const providedToolSubitems = [
  `To read files use Read instead of cat, head, tail, or sed`,
  `To search for files use Glob instead of find or ls`,
  `To search the content of files, use Grep instead of grep or rg`,
]
```

### 4. 先搜索后读取

AI 的典型模式是先用 `Glob`/`Grep` 找到文件路径，再用 `Read` 读取具体内容——而非盲目读取所有文件。

### 5. 子代理保护上下文

对于大规模探索，Explore 子代理在独立上下文中工作，只返回精炼报告，避免大量原始搜索结果填满主上下文窗口。系统提示词明确要求不重复劳动：

```
if you delegate research to a subagent, do not also perform the same searches yourself.
```

### 6. 偏向行动

在 Proactive 模式下，AI 被要求无需用户确认即可探索：

```
Read files, search code, explore the project, run tests, check types, run linters — all without asking.
```

## 七、 无内置目录树工具

### 1. 没有 LS 工具

Claude Code **没有内置的 LS/目录树工具**。如果需要查看目录结构，AI 有两种替代方式：

| 方式 | 示例 | 说明 |
|------|------|------|
| 用 `Glob` 模拟 | `Glob("*")`、`Glob("src/*")` | 按模式列出文件，推荐方式 |
| 用 `Bash` 执行 | `ls -la`、`tree` | 系统提示词不鼓励，除非必要 |

### 2. CLAUDE.md 生成时的指导

`/init` 命令生成 `CLAUDE.md` 时，[`init.ts`](../../claude-code-source/src/commands/init.ts#L15) 明确指导 AI 不要罗列所有文件结构：

```typescript
// src/commands/init.ts
`- Avoid listing every component or file structure that can be easily discovered.`
```

这进一步印证了 Claude Code 的设计哲学：文件结构是可以通过工具按需发现的，不需要预先全量列出。

### 3. Glob 作为目录列表的替代

| 需求 | Glob 模式 | 等效 Bash |
|------|-----------|-----------|
| 列出根目录文件 | `*` | `ls` |
| 列出 src 目录 | `src/*` | `ls src/` |
| 递归列出所有 TS 文件 | `**/*.ts` | `find . -name "*.ts"` |
| 列出所有配置文件 | `**/*.{json,yaml,yml,toml}` | `find . -name "*.json" -o -name "*.yaml"` |

## 九、 实际示例

### 1. 典型探索序列

假设用户要求"分析这个项目的架构"，AI 的实际工具调用序列可能如下：

**第一轮（广度扫描，并行）：**

```
Glob("**/package.json")     → 发现是 Node.js 项目
Glob("**/*.ts")             → 发现 457 个 TS 文件
Glob("**/*.md")             → 发现 2 个 MD 文件
Read("README.md")           → 读取项目说明
Read("package.json")        → 读取依赖和脚本
```

**第二轮（定向搜索，并行）：**

```
Glob("src/**/index.ts")     → 找到入口文件
Grep("export.*function")    → 了解导出的函数
Grep("class.* extends")     → 找到类继承关系
Read("src/index.ts")        → 读取入口文件
```

**第三轮（委派子代理，如果需要更深入）：**

```
Task(
  subagent_type="Explore",
  prompt="very thorough: 分析 src/tools 目录下所有工具的注册机制和调用流程"
)
```

### 2. 工具调用次数

一个典型的项目结构分析任务，AI 的工具调用次数通常在 5-15 次之间，而非数百次。这是因为：

- 并行调用减少了轮次
- 模式匹配替代了逐文件检查
- 子代理消化了大量原始搜索结果
