## 一、 概述

探索决策分层机制是 Claude Code 引导 LLM 在面对代码库探索任务时做出工具选择的核心逻辑。该机制通过系统提示词注入，在 LLM 上下文中建立一套"简单搜索 → 子代理探索 → 后台研究"的三级递进决策框架，确保探索行为在效率与上下文保护之间取得平衡。

本文档详细分析决策分层的完整逻辑、工具偏好规则、并行调用指导、以及系统提示词中的各注入点。

## 二、 决策分层的核心逻辑

### 1. 三级递进框架

探索决策分为三个层级，每层对应不同的工具使用策略：

| 层级 | 场景 | 工具 | 触发条件 |
|------|------|------|----------|
| 第一级 | 简单定向搜索 | `Glob`/`Grep`/`Read` 直接调用 | 默认优先 |
| 第二级 | 广泛代码库探索 | `Task` + `Explore` 子代理 | 预计查询 > 3 次 |
| 第三级 | 后台异步研究 | `Task` 创建 Fork | Fork 模式启用 |

### 2. 核心阈值常量

决策分层的核心阈值定义在 [`exploreAgent.ts`](../../claude-code-source/src/tools/AgentTool/built-in/exploreAgent.ts#L59)：

```typescript
// src/tools/AgentTool/built-in/exploreAgent.ts
export const EXPLORE_AGENT_MIN_QUERIES = 3
```

该常量被系统提示词引用，作为 LLM 判断是否升级到子代理探索的依据。

### 3. 决策逻辑注入点

决策分层逻辑通过 [`getUsingYourToolsSection()`](../../claude-code-source/src/constants/prompts.ts#L269-L399) 注入系统提示词的 Session-specific guidance 部分：

```typescript
// src/constants/prompts.ts
const items = [
  // ... 其他指导项 ...
  ...(hasAgentTool &&
  areExplorePlanAgentsEnabled() &&
  !isForkSubagentEnabled()
    ? [
        `For simple, directed codebase searches (e.g. for a specific file/class/function) use ${searchTools} directly.`,
        `For broader codebase exploration and deep research, use the ${AGENT_TOOL_NAME} tool with subagent_type=${EXPLORE_AGENT.agentType}. This is slower than using ${searchTools} directly, so use this only when a simple, directed search proves to be insufficient or when your task will clearly require more than ${EXPLORE_AGENT_MIN_QUERIES} queries.`,
      ]
    : []),
  // ... 其他指导项 ...
]
```

### 4. 启用条件

决策分层指导仅在以下三个条件同时满足时注入：

| 条件 | 含义 | 来源 |
|------|------|------|
| `hasAgentTool` | Agent 工具可用 | 工具注册检查 |
| `areExplorePlanAgentsEnabled()` | Explore/Plan Agent 已启用 | GrowthBook `tengu_amber_stoat` flag，默认 true |
| `!isForkSubagentEnabled()` | Fork 模式未启用 | Fork 模式有自己的委派逻辑 |

当 Fork 模式启用时，系统提示词使用不同的 Agent 工具指导（详见下文第四节）。

### 5. 搜索工具名称解析

`searchTools` 变量根据是否使用嵌入式搜索工具而变化：

```typescript
// src/constants/prompts.ts
const searchTools = hasEmbeddedSearchTools()
  ? `\`find\` or \`grep\` via the ${BASH_TOOL_NAME} tool`
  : `the ${GLOB_TOOL_NAME} or ${GREP_TOOL_NAME}`
```

- **标准构建**：指向专用 `Glob`/`Grep` 工具
- **嵌入式构建**（Ant-native）：`find`/`grep` 通过 Bash 调用，因嵌入式构建移除了专用工具

## 三、 工具偏好规则

### 1. 专用工具优先于 Bash

系统提示词通过 [`getUsingYourToolsSection()`](../../claude-code-source/src/constants/prompts.ts#L269-L314) 强制要求 AI 优先使用专用工具：

```typescript
// src/constants/prompts.ts
const providedToolSubitems = [
  `To read files use ${FILE_READ_TOOL_NAME} instead of cat, head, tail, or sed`,
  `To edit files use ${FILE_EDIT_TOOL_NAME} instead of sed or awk`,
  `To create files use ${FILE_WRITE_TOOL_NAME} instead of cat with heredoc or echo redirection`,
  ...(embedded
    ? []
    : [
        `To search for files use ${GLOB_TOOL_NAME} instead of find or ls`,
        `To search the content of files, use ${GREP_TOOL_NAME} instead of grep or rg`,
      ]),
  `Reserve using the ${BASH_TOOL_NAME} exclusively for system commands and terminal operations that require shell execution. If you are unsure and there is a relevant dedicated tool, default to using the dedicated tool and only fallback on using the ${BASH_TOOL_NAME} tool for these if it is absolutely necessary.`,
]
```

### 2. 工具映射表

| 操作 | 专用工具 | 禁止使用的 Bash 命令 |
|------|----------|---------------------|
| 读取文件 | `Read` | `cat`、`head`、`tail`、`sed` |
| 搜索文件 | `Glob` | `find`、`ls` |
| 搜索内容 | `Grep` | `grep`、`rg` |
| 编辑文件 | `Edit` | `sed`、`awk` |
| 创建文件 | `Write` | `cat` heredoc、`echo` 重定向 |

### 3. REPL 模式例外

在 REPL 模式下，Read/Write/Edit/Glob/Grep/Bash/Agent 工具对 LLM 隐藏（属于 `REPL_ONLY_TOOLS`），因此"专用工具优先于 Bash"的指导不注入，由 REPL 自身的提示词覆盖工具调用方式：

```typescript
// src/constants/prompts.ts
if (isReplModeEnabled()) {
  const items = [
    taskToolName
      ? `Break down and manage your work with the ${taskToolName} tool.`
      : null,
  ].filter(item => item !== null)
  if (items.length === 0) return ''
  return [`# Using your tools`, ...prependBullets(items)].join(`\n`)
}
```

## 四、 并行调用指导

### 1. 最大化并行原则

系统提示词明确鼓励 AI 并行调用无依赖的工具：

```typescript
// src/constants/prompts.ts
`You can call multiple tools in a single response. If you intend to call multiple tools and there are no dependencies between them, make all independent tool calls in parallel. Maximize use of parallel tool calls where possible to increase efficiency. However, if some tool calls depend on previous calls to inform dependent values, do NOT call these tools in parallel and instead call them sequentially. For instance, if one operation must complete before another starts, run these operations sequentially instead.`
```

### 2. 依赖判断规则

| 调用模式 | 条件 | 示例 |
|----------|------|------|
| 并行调用 | 工具间无依赖 | 同时读取 3 个已知路径的文件 |
| 顺序调用 | 后续调用依赖前序结果 | 先 `Grep` 搜索函数定义，再 `Read` 读取找到的文件 |

### 3. Explore 子代理的并行优化

Explore 子代理的系统提示词同样强调并行调用：

```
Wherever possible you should try to spawn multiple parallel tool calls for grepping and reading files
```

## 五、 Agent 工具指导

### 1. 标准模式指导

当 Fork 模式未启用时，Agent 工具的指导由 [`getAgentToolSection()`](../../claude-code-source/src/constants/prompts.ts#L316-L320) 提供：

```typescript
// src/constants/prompts.ts
function getAgentToolSection(): string {
  return isForkSubagentEnabled()
    ? `Calling ${AGENT_TOOL_NAME} without a subagent_type creates a fork...`
    : `Use the ${AGENT_TOOL_NAME} tool with specialized agents when the task at hand matches the agent's description. Subagents are valuable for parallelizing independent queries or for protecting the main context window from excessive results, but they should not be used excessively when not needed. Importantly, avoid duplicating work that subagents are already doing - if you delegate research to a subagent, do not also perform the same searches yourself.`
}
```

### 2. Fork 模式指导

当 Fork 模式启用时，Agent 工具的指导变为：

```
Calling Agent without a subagent_type creates a fork, which runs in the background and keeps its tool output out of your context — so you can keep chatting with the user while it works. Reach for it when research or multi-step implementation work would otherwise fill your context with raw output you won't need again. If you ARE the fork — execute directly; do not re-delegate.
```

### 3. 子代理使用原则

| 原则 | 说明 |
|------|------|
| 并行化独立查询 | 多个无依赖的搜索任务可委派给不同子代理 |
| 保护主上下文 | 大量原始搜索结果由子代理消化，仅返回精炼报告 |
| 不过度使用 | 简单任务直接用 `Glob`/`Grep` 即可 |
| 避免重复 | 委派后主代理不应重复相同搜索 |

## 六、 Proactive 模式下的探索行为

### 1. 偏向行动原则

在 Proactive 模式下，[`getProactiveSection()`](../../claude-code-source/src/constants/prompts.ts#L860-L913) 注入额外的探索行为指导：

```
## Bias toward action

Act on your best judgment rather than asking for confirmation.

- Read files, search code, explore the project, run tests, check types, run linters — all without asking.
- Make code changes. Commit when you reach a good stopping point.
- If you're unsure between two reasonable approaches, pick one and go. You can always course-correct.
```

### 2. 面对模糊性的行为

```
Look for useful work. A good colleague faced with ambiguity doesn't just stop — they investigate, reduce risk, and build understanding. Ask yourself: what don't I know yet? What could go wrong? What would I want to verify before calling this done?
```

### 3. 首次唤醒限制

Proactive 模式的首次唤醒**禁止**主动探索代码库：

```
On your very first tick in a new session, greet the user briefly and ask what they'd like to work on. Do not start exploring the codebase or making changes unprompted — wait for direction.
```

### 4. 终端焦点校准

系统根据终端焦点状态调整自主探索程度：

| 终端状态 | 探索行为 |
|----------|----------|
| 未聚焦（用户离开） | 倾向自主行动 — 决策、探索、提交、推送 |
| 已聚焦（用户观看） | 更协作 — 呈现选项，大变更前询问 |

## 七、 先读后改原则

### 1. 核心规则

系统提示词中的核心指导：

```typescript
// src/constants/prompts.ts
`In general, do not propose changes to code you haven't read. If a user asks about or wants you to modify a file, read it first. Understand existing code before suggesting modifications.`,
```

### 2. 实践含义

该规则要求 AI 在以下场景中必须先读取文件：

- 用户要求修改某个文件时
- AI 提议对代码进行变更时
- 分析代码逻辑并给出建议时

## 八、 Plan 模式中的探索指导

### 1. 只读工具集

Plan 模式中，[`getReadOnlyToolNames()`](../../claude-code-source/src/utils/messages.ts#L3299-L3314) 返回允许使用的只读工具：

```typescript
// src/utils/messages.ts
function getReadOnlyToolNames(): string {
  const tools = hasEmbeddedSearchTools()
    ? [FILE_READ_TOOL_NAME, '`find`', '`grep`']
    : [FILE_READ_TOOL_NAME, GLOB_TOOL_NAME, GREP_TOOL_NAME]
  const { allowedTools } = getCurrentProjectConfig()
  const filtered =
    allowedTools && allowedTools.length > 0 && !hasEmbeddedSearchTools()
      ? tools.filter(t => allowedTools.includes(t))
      : tools
  return filtered.join(', ')
}
```

### 2. Explore Agent 推荐

Plan 模式系统提示词中，当 Explore/Plan Agent 启用时，推荐使用 Explore 子代理并行化复杂搜索：

```typescript
// src/utils/messages.ts
1. **Explore** — Use ${getReadOnlyToolNames()} to read code. Look for existing functions, utilities, and patterns to reuse.${areExplorePlanAgentsEnabled() ? ` You can use the ${EXPLORE_AGENT.agentType} agent type to parallelize complex searches without filling your context, though for straightforward queries direct tools are simpler.` : ''}
```

### 3. 迭代探索循环

Plan 模式采用"探索 → 更新计划 → 询问用户"的迭代循环：

```
1. **Explore** — Use read-only tools to read code
2. **Update the plan file** — After each discovery, immediately capture what you learned
3. **Ask the user** — When you hit an ambiguity, use AskUserQuestion
```

详细的 Plan 模式工作流见 [LV203](LV203-Plan模式与迭代规划工作流.md)。
