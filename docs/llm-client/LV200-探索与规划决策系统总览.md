## 一、 概述

Claude Code 的探索与规划决策系统是一套指导 LLM 何时探索代码库、使用何种工具探索、以及如何将探索成果转化为实施计划的决策框架。该系统通过系统提示词注入、内置 Agent 定义、Plan 模式工作流三个层面协同工作，确保 AI 在面对代码库时的行为既高效又可控。

本文档是探索与规划决策系统的总体概述，涵盖核心概念、整体架构、决策分层逻辑与核心源码索引。各子系统的详细介绍见后续文档。

## 二、 核心概念

| 概念 | 说明 |
|------|------|
| **探索决策分层** | AI 根据任务复杂度在"直接搜索"与"Explore 子代理"之间选择，阈值为 3 次查询 |
| **Explore Agent** | 只读子代理，使用 `haiku` 模型快速搜索代码库，保护主上下文窗口 |
| **Plan Agent** | 只读子代理，继承主模型，负责架构设计与实施规划 |
| **Plan 模式** | 用户指示的只读规划模式，AI 探索代码并逐步撰写计划文件，不允许修改系统 |
| **EXPLORE_AGENT_MIN_QUERIES** | 探索决策阈值常量，值为 3，决定何时从直接搜索升级为子代理探索 |
| **Proactive 探索** | 自主模式下"偏向行动"原则驱动的不需用户确认的探索行为 |
| **只读工具集** | `Read`、`Glob`、`Grep` 三个专用工具，是探索阶段的核心工具池 |

## 五、 决策分层总览

### 1. 三级递进决策

AI 在面对需要理解代码库的任务时，遵循以下分层决策：

| 层级 | 触发条件 | 使用工具 | 特点 |
|------|----------|----------|------|
| 第一级：简单定向搜索 | 预计查询次数 ≤ 3 | `Glob`、`Grep`、`Read` 直接调用 | 快速、低延迟、结果直接进入主上下文 |
| 第二级：深度代码库探索 | 预计查询次数 > 3 | `Task` 工具 + `Explore` 子代理 | 并行搜索、保护主上下文、使用 `haiku` 模型 |
| 第三级：后台异步研究 | Fork 模式启用时 | `Task` 工具创建 Fork | 后台运行、不阻塞用户交互、共享缓存 |

核心决策逻辑注入在系统提示词的 Session-specific guidance 部分：

```typescript
// src/constants/prompts.ts
...(hasAgentTool &&
areExplorePlanAgentsEnabled() &&
!isForkSubagentEnabled()
  ? [
      `For simple, directed codebase searches (e.g. for a specific file/class/function) use ${searchTools} directly.`,
      `For broader codebase exploration and deep research, use the ${AGENT_TOOL_NAME} tool with subagent_type=${EXPLORE_AGENT.agentType}. This is slower than using ${searchTools} directly, so use this only when a simple, directed search proves to be insufficient or when your task will clearly require more than ${EXPLORE_AGENT_MIN_QUERIES} queries.`,
    ]
  : []),
```

### 2. 工具偏好规则

系统提示词强制要求 AI 优先使用专用工具而非 Bash：

- 读取文件 → 使用 `Read` 而非 `cat`、`head`、`tail`、`sed`
- 搜索文件 → 使用 `Glob` 而非 `find` 或 `ls`
- 搜索内容 → 使用 `Grep` 而非 `grep` 或 `rg`
- 编辑文件 → 使用 `Edit` 而非 `sed` 或 `awk`
- 创建文件 → 使用 `Write` 而非 `cat` heredoc 或 `echo` 重定向

### 3. 并行调用原则

系统提示词鼓励 AI 最大化并行工具调用：

```typescript
// src/constants/prompts.ts
`You can call multiple tools in a single response. If you intend to call multiple tools and there are no dependencies between them, make all independent tool calls in parallel. Maximize use of parallel tool calls where possible to increase efficiency.`
```

## 六、 探索行为核心原则

### 1. 先读后改

系统提示词要求 AI 在提议修改前必须先读取并理解现有代码：

```typescript
// src/constants/prompts.ts
`In general, do not propose changes to code you haven't read. If a user asks about or wants you to modify a file, read it first. Understand existing code before suggesting modifications.`,
```

### 2. 偏向行动

在 Proactive 模式下，AI 被要求无需用户确认即可探索：

```
Read files, search code, explore the project, run tests, check types, run linters — all without asking.
```

### 3. 面对模糊性主动调查

```
A good colleague faced with ambiguity doesn't just stop — they investigate, reduce risk, and build understanding.
Ask yourself: what don't I know yet? What could go wrong? What would I want to verify before calling this done?
```

### 4. 不重复劳动

当已委托子代理进行研究时，主代理不应重复相同的搜索：

```
if you delegate research to a subagent, do not also perform the same searches yourself.
```

## 七、 Agent 工具使用哲学

Agent 工具（`Task`/`Agent`）的子代理委派遵循以下原则：

- **并行化独立查询** — 多个无依赖的搜索任务可委派给不同子代理并行执行
- **保护主上下文** — 大量原始搜索结果由子代理消化，仅返回精炼报告
- **不过度使用** — 简单任务直接用 `Glob`/`Grep` 即可，无需子代理开销
- **避免重复** — 委派后主代理不应重复相同搜索

## 八、 探索与规划的边界

系统明确区分了"探索/研究"与"规划实现"两种场景：

| 场景 | 使用工具 | 是否进入 Plan 模式 |
|------|----------|-------------------|
| 搜索文件、理解代码库、回答问题 | `Glob`/`Grep`/`Read` 或 Explore 子代理 | 否 |
| 规划编码任务的实施步骤 | Plan 模式 + `ExitPlanMode` 工具 | 是 |

ExitPlanMode 工具的提示词明确指出：

```
IMPORTANT: Only use this tool when the task requires planning the implementation steps of a task that requires writing code. For research tasks where you're gathering information, searching files, reading files or in general trying to understand the codebase - do NOT use this tool.
```
